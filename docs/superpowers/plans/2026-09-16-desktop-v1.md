# 外贸数字员工 Desktop V1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 把现有已经验证过的外贸数字员工核心封装成 macOS + Windows 共用源码的 PySide6 桌面应用，让普通用户无需 Python、Git、VS Code 或终端即可完成首次配置、历史学习、安全 baseline、后台轮询、AI 草稿和企业微信提醒，同时保持“只生成草稿，绝不自动发送”的安全边界。

**Architecture:** 新增 `desktop/` 包作为配置、状态、调度、平台适配和 PySide6 UI 层；现有 `mail_reader`、`mail_writer`、`agent`、`history_learning`、`wecom` 继续作为唯一业务实现。桌面层通过显式配置对象和可注入路径调用现有批处理入口，CLI `.env` 入口继续保留用于开发兼容。macOS/Windows 的凭据、自启动和用户数据目录差异封装在 adapter 中。

**Tech Stack:** Python 3、PySide6、pytest、stdlib `json/pathlib/threading/hashlib/zipfile/logging`、`keyring`、`platformdirs`、PyInstaller；Windows 安装器使用 Inno Setup；现有 IMAP/LLM/SQLite/WeCom 核心保持不变。

**Spec:** `docs/superpowers/specs/2026-09-16-desktop-v1-design.md`

## Global Constraints

- macOS 与 Windows 共用一套 Python 业务源码，但安装包必须在目标操作系统原生构建和验证。
- V1 单机、单用户、单邮箱，仅支持 163 邮箱。
- `Reply Draft` 始终为英文；继续保留客户语言识别、中文翻译和中文回译。
- 任何路径都不得自动向客户发送邮件；Desktop V1 不提供发送按钮。
- Fresh Install 必须先完成用户主动触发的历史学习并建立 processed baseline，之后才能启用生产轮询。
- 历史邮件只学习，不生成草稿；baseline 之后的新邮件才进入自动处理。
- 默认轮询间隔为 180 秒；“立即检查一次”必须复用同一个生产处理入口。
- 关闭主窗口不等于退出应用；明确“退出外贸数字员工”才停止后台运行。
- 邮箱授权码、AI API Key、企业微信 Webhook 不得明文进入普通配置文件、日志、诊断包、Git 或安装包。
- 正式桌面运行不得依赖 `.env` 才能启动；开发 CLI 仍允许继续使用 `.env`。
- macOS 敏感凭据使用 Keychain，Windows 使用 Credential Manager，通过 `keyring` 统一封装。
- 连续失败 3 次进入 `NEEDS_ATTENTION`，连续失败 5 次或明确不可恢复的认证/配置错误进入 `SERVICE_ERROR`；一次完整成功重置对应失败计数。
- 日志默认保留 30 天，不记录完整客户正文或任何敏感凭据。
- 普通备份不包含邮箱授权码、AI API Key、企业微信 Webhook。
- 升级/重装程序不得删除历史学习数据库、客户记忆、配置或 processed Message-ID 状态。
- 每项代码变更遵循 RED -> GREEN -> focused regression -> full regression；真实邮箱和安装包测试在对应阶段执行。
- 不允许通过删除、跳过或弱化现有测试换取通过率。

- [ ] **Step 3: 实现 `DesktopPaths`**

```python
from dataclasses import dataclass
from pathlib import Path
from platformdirs import user_data_path

APP_NAME = "ForeignTradeDigitalEmployee"
APP_AUTHOR = "ForeignTradeDigitalEmployee"

@dataclass(frozen=True)
class DesktopPaths:
    root: Path
    settings_file: Path
    pin_file: Path
    history_db: Path
    processed_store: Path
    result_dir: Path
    log_dir: Path
    backup_dir: Path

    @classmethod
    def from_root(cls, root: Path) -> "DesktopPaths":
        return cls(
            root=root,
            settings_file=root / "settings.json",
            pin_file=root / "admin_pin.json",
            history_db=root / "history_learning.db",
            processed_store=root / "processed_message_ids.txt",
            result_dir=root / "result",
            log_dir=root / "logs",
            backup_dir=root / "backups",
        )

    @classmethod
    def for_current_user(cls) -> "DesktopPaths":
        return cls.from_root(Path(user_data_path(APP_NAME, APP_AUTHOR)))

    def ensure(self) -> None:
        self.root.mkdir(parents=True, exist_ok=True)
        self.result_dir.mkdir(parents=True, exist_ok=True)
        self.log_dir.mkdir(parents=True, exist_ok=True)
        self.backup_dir.mkdir(parents=True, exist_ok=True)
```

```python
from typing import Protocol
import keyring

SERVICE_NAME = "foreign-trade-digital-employee"
EMAIL_AUTH_CODE = "email_auth_code"
AI_API_KEY = "ai_api_key"
WECOM_WEBHOOK = "wecom_webhook"

class CredentialStore(Protocol):
    def get(self, key: str) -> str | None: ...
    def set(self, key: str, value: str) -> None: ...
    def delete(self, key: str) -> None: ...

class KeyringCredentialStore:
    def __init__(self, service_name: str = SERVICE_NAME):
        self.service_name = service_name

    def get(self, key: str) -> str | None:
        return keyring.get_password(self.service_name, key)

    def set(self, key: str, value: str) -> None:
        keyring.set_password(self.service_name, key, value)

    def delete(self, key: str) -> None:
        try:
            keyring.delete_password(self.service_name, key)
        except keyring.errors.PasswordDeleteError:
            pass
```

同时实现只用于测试的 `MemoryCredentialStore`，不要让业务测试调用真实 Keychain/Credential Manager。
