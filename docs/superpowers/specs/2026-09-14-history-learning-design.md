# 历史邮件学习与客户记忆设计（V1）

日期：2026-09-14

## 1. 目标

在不改变现有安全逻辑的前提下，为“外贸数字员工”增加历史邮件学习能力：

- 用户主动点击一次“学习我的历史邮件”。
- 读取最近 6 个月的有效历史邮件，最多 1000 封。
- 只读取收件箱（INBOX）和已发送邮件（Sent）。
- 从历史邮件中建立用户本人的“回复风格档案”。
- 建立客户/联系人历史索引，在新询盘到来时提供必要的上下文。
- 后续自动增量读取新增的已发送邮件，让风格和客户上下文持续更新。
- 新询盘仍然只生成并保存草稿，永远不自动发送给客户。

本设计先完成“学习引擎”本身。Windows 桌面界面、安装包和一键配置作为后续独立子项目接入该引擎，避免一次性改动过大。

## 2. V1 范围

### 2.1 初次学习

用户必须主动触发学习，不在绑定邮箱后偷偷扫描历史邮件。

默认规则：

- 时间范围：最近 6 个月。
- 邮件上限：1000 封。
- 如果 6 个月内不足 1000 封，有多少处理多少。
- 如果超过 1000 封，按邮件日期从新到旧保留最近 1000 封。
- 超过 6 个月的旧邮件默认不处理。
- 仅处理 INBOX 和 Sent。
- 验证码、系统通知、广告、订阅、noreply 等非客户邮件继续复用现有过滤规则排除。

### 2.2 后续增量学习

初次学习完成后：

- 自动检测 Sent 中新增的邮件。
- 只学习真正已经发送出去的最终邮件。
- 草稿箱内容不参与学习。
- AI 生成但用户没有发送的草稿不参与学习。
- 新增 Sent 邮件先写入本地历史索引，再更新回复风格和客户上下文。
- 同一封邮件通过 Message-ID 去重，不能重复学习。

## 3. 安全边界

以下规则不可被历史学习覆盖：

1. 系统仍然只创建邮件草稿，不自动发送。
2. 历史价格、交期、库存、折扣、付款条件、Incoterm 等商业信息只能作为“过去发生过什么”的背景，不能自动视为当前仍有效。
3. 当前邮件中没有确认的信息，AI 不得因为历史邮件中曾出现过而擅自承诺。
4. 现有 Output Gate 和 SKILL.md 安全规则继续拥有更高优先级。
5. 历史学习失败不能破坏现有新邮件处理流程。
6. 学习历史邮箱时只读，不改变邮件已读/未读状态，不移动、不删除邮件。

## 4. 数据与隐私原则

采用“本地优先”。

- 历史邮件索引、风格档案、客户记忆均保存在用户自己的电脑。
- V1 不建立中心化服务器，不把整套邮箱历史上传到开发者服务器。
- 不批量把 1000 封原始邮件全部发送给 AI。
- 初次风格学习只选择有限数量的代表性 Sent 回复作为风格样本，并结合本地统计生成风格档案。
- 生成新回复时，只向 AI 提供当前邮件、必要的风格档案、必要的同客户历史上下文，而不是整套历史邮箱。

## 5. 本地存储

V1 使用 SQLite，原因：

- Windows / macOS 都可用。
- 不需要用户安装数据库。
- 对最多约 1000 封初始邮件和后续增量足够轻量。
- 方便以后桌面应用读取状态和统计。

建议本地数据库：

`runtime/history_learning.db`

主要数据：

### 5.1 email_history

保存已经进入学习索引的邮件：

- message_id
- mailbox（INBOX / Sent）
- direction（incoming / outgoing）
- sender
- recipients
- subject
- sent_at
- normalized_body
- customer_email
- customer_name（如果能可靠提取）
- company_name（如果能可靠提取）
- company_domain

Message-ID 必须唯一。

### 5.2 style_profile

保存当前用户回复风格档案，例如：

- preferred_tone
- typical_length
- greeting_pattern
- closing_pattern
- structure_preferences
- wording_preferences
- manual_overrides
- updated_at

用户以后在桌面端手动修改的内容保存在 `manual_overrides`，其优先级高于自动学习结果。

### 5.3 customer_memory

保存客户级别的结构化记忆：

- customer_email
- customer_name
- company_name
- company_domain
- last_contact_at
- recent_products
- recent_topics
- last_thread_summary

商业条款只记录为历史背景，不写成“当前有效事实”。

### 5.4 learning_state

记录：

- initial_learning_completed
- initial_learning_started_at
- initial_learning_finished_at
- last_sent_sync_at
- last_sent_message_id / checkpoint
- scanned_count
- learned_count
- skipped_count
- failed_count

## 6. 客户身份识别

用户不需要配置匹配规则，系统默认自动处理。

优先级：

1. 邮箱地址精确匹配。
2. 公司域名辅助判断。
3. 公司名辅助判断。
4. 不确定时不自动合并。

同一公司不同联系人保持各自联系人身份，但允许共享公司级背景。

例如：

- pierre@euromotion.com
- alice@euromotion.com

可以识别为同一公司下两个联系人，但不能把两个人的联系人身份合并成一个人。

## 7. Sent 文件夹发现

163 邮箱的“已发送”目录名称可能因 IMAP 表现不同而变化，因此不能把目录名硬编码为单一字符串。

发现顺序：

1. 通过 IMAP `LIST` 查找带 `\\Sent` special-use 标记的目录。
2. 如果没有 special-use 标记，再匹配常见目录名（如 Sent、Sent Messages、已发送等）。
3. 如果仍找不到，初次学习可以继续处理 INBOX，但明确报告“未找到已发送目录，回复风格学习不完整”。
4. 后续桌面端高级设置可预留手动选择 Sent 目录，但 V1 普通用户界面不暴露该配置。

## 8. 回复风格学习

V1 不做模型微调，也不把历史内容“训练进模型”。

采用“本地统计 + 有限样本总结”的方式：

1. 从有效 Sent 邮件中提取基础统计：
   - 平均回复长度。
   - 常用称呼。
   - 常用结尾。
   - 段落/列表习惯。
   - 常见签名模式。
2. 从 6 个月历史中选择有限数量的代表性 Sent 回复作为样本。
3. 使用现有 LLM 生成结构化风格档案。
4. 风格档案必须可查看、可编辑。
5. 手工修改优先于后续自动学习，自动学习不得静默覆盖用户明确设置。

V1 不引入向量数据库，不做复杂 embedding 检索。

## 9. 新询盘生成上下文

处理一封新的客户邮件时，Agent 输入由以下部分组成：

1. 当前客户邮件。
2. 现有 SKILL.md 安全规则。
3. 用户回复风格档案。
4. 与该客户邮箱匹配的最近历史往来。
5. 必要时加入同公司背景。

历史上下文默认只选取有限的最近邮件，避免把大量旧邮件塞进 prompt。

建议默认：

- 同客户最近 3 个有效往来回合，或
- 不超过固定字符/Token 预算。

若没有历史：

- 按现有 Agent 逻辑正常生成。
- 仅使用全局回复风格档案。

## 10. 增量学习更新策略

每次正式运行时可以执行轻量 Sent 增量同步：

1. 查找上次 checkpoint 之后的新 Sent 邮件。
2. 按 Message-ID 去重。
3. 写入 `email_history`。
4. 更新对应客户的 `customer_memory`。
5. 如果本轮存在新增 Sent 邮件，则最多触发一次风格档案增量更新。

这样不会每封邮件都重复重建整个 6 个月历史。

## 11. 与现有流程的集成

当前正式处理链保持主体不变：

`读取新邮件 -> eligibility -> build_agent_payload -> AI -> Output Gate -> 保存分析 -> 创建草稿 -> mark processed -> 企业微信通知`

增加历史能力后：

`读取新邮件 -> eligibility -> 加载风格/客户历史上下文 -> build_agent_payload -> AI -> Output Gate -> 保存分析 -> 创建草稿 -> mark processed -> 企业微信通知`

历史学习模块作为上下文提供者，不直接负责发送邮件。

## 12. 失败处理

### 初次学习失败

- 单封历史邮件解析失败：记录失败并继续。
- Sent 文件夹不可用：允许 INBOX 索引继续，但风格学习标记为不完整。
- AI 风格总结失败：保留已经建立的本地邮件索引，不影响现有邮件草稿功能。
- 数据库写入失败：停止本次学习，不能声称学习完成。

### 增量学习失败

- 不影响当前新邮件的草稿生成。
- 不更新 checkpoint，确保下次仍可以重试。
- 不允许因为学习失败而重复发送企业微信询盘通知或重复生成同一封新邮件的草稿。

## 13. 用户界面要求（供后续 Windows 桌面项目使用）

普通用户只需要看到：

- “学习我的历史邮件”按钮。
- 学习进度。
- 学习结果：已学习邮件数 / 已建立回复风格 / 已识别客户历史。
- “我的回复风格”查看与编辑入口。

默认值隐藏在后台：

- 6 个月。
- 最多 1000 封。
- INBOX + Sent。
- 客户匹配规则。
- 增量学习。

除非用户主动进入高级设置，否则不要求理解这些概念。

## 14. V1 明确不做

本子项目不实现：

- 自动发送客户邮件。
- Gmail / Outlook / QQ 邮箱支持。
- 多用户、多 Profile。
- 企业微信双向聊天控制。
- 云端历史邮件库。
- 向量数据库。
- 模型微调。
- Windows GUI、PyInstaller、Inno Setup 安装包。
- macOS 桌面打包。

这些能力不阻塞未来扩展，但不能扩大本次实施范围。

## 15. 测试与验收

实施必须采用测试先行，并保持现有测试全部通过。

至少覆盖：

1. 6 个月日期过滤。
2. 1000 封上限及按日期取最近邮件。
3. INBOX / Sent 读取为只读。
4. Sent 文件夹发现。
5. 非客户邮件过滤。
6. Message-ID 去重。
7. 只学习 Sent 的最终发送邮件，不学习 Draft。
8. 客户邮箱优先匹配。
9. 公司域名辅助匹配。
10. 不确定客户不强制合并。
11. 历史商业信息不会被标成当前有效事实。
12. 风格档案可生成并支持手工 override。
13. 新询盘上下文只选取有限历史。
14. 增量 Sent 同步不会重复学习。
15. 学习失败不破坏现有草稿流程。
16. 任何路径都不得自动发送客户邮件。
17. 现有全部回归测试继续通过。

真实验收：

- 使用测试 163 邮箱执行一次初次学习。
- 验证扫描范围为最近 6 个月且不超过 1000 封。
- 验证建立的风格档案与实际历史 Sent 回复基本一致。
- 使用一个已有历史客户发新询盘，确认草稿能体现历史风格和必要上下文。
- 使用一个新客户发询盘，确认不会错误套用其他客户历史。
- 用户手工修改并发送一封邮件后，确认下一次增量同步可以学习新的 Sent 最终版本。
- 再次运行不能重复学习同一 Message-ID。
- 全流程仍然只保存草稿，不自动发送。
