# 外贸数字员工 Desktop V1 Fluent UI 设计补充

日期：2026-09-17

状态：待用户最终审阅

> 本文是 `2026-09-16-desktop-v1-design.md` 的视觉与交互补充规范。它不改变既有业务核心、安全边界和桌面总体架构，只覆盖并细化 Dashboard、首次配置向导、普通设置、管理员设置、错误状态和托盘交互的 UI/UX 设计。

## 1. 目标

把当前已经可运行的 PySide6 QWidget 桌面壳，从“默认 Qt 工具软件感”升级为适合长期交付给普通外贸用户使用的正式桌面产品，同时保持：

- 不重写现有业务核心。
- 不改动邮件处理、AI、历史学习、去重、草稿保存和企业微信顺序。
- 不在桌面端提供“发送客户邮件”按钮。
- 不降低首次历史学习与 processed baseline 的安全 Gate。
- macOS 与 Windows 共用同一套 UI 业务源码。

成功标准：普通用户第一次看到软件时，界面应更接近 Microsoft 365 / Fluent 2 / Linear / Notion 一类现代生产力软件，而不是默认 Qt 控件堆叠。

## 2. 已确认视觉方向

Desktop V1 采用：

**商务高级浅色 Fluent 风 + macOS 极简克制感。**

视觉关键词：

- 浅色。
- 冷灰白背景。
- 白色圆角卡片。
- 单一商务蓝作为主强调色。
- 绿色状态点表示正常。
- 极轻边框和阴影。
- 高信息层级、低视觉噪声。
- 不使用大面积渐变、霓虹、科技大屏风格。
- 不在正常状态里大量使用 Emoji。

V1 **只实现高质量浅色模式**。深色模式明确放到后续版本，不作为 V1 验收要求。

## 3. 技术路线

### 3.1 保留 QWidget

继续使用现有 PySide6 QWidget 架构，不迁移到 QML。

原因：

- 现有 Dashboard、Scheduler、测试和回调已经基于 QWidget。
- QML 会扩大 UI 层改造范围和测试成本。
- V1 的目标是稳定交付，不是追求复杂动画。

### 3.2 不直接绑定第三方 Fluent 商业组件库

可以参考 PyQt-Fluent-Widgets、PySide6-FluentUI-QML、qt-material、QDarkStyleSheet 的布局与视觉语言，但 V1 不直接依赖存在许可证或架构约束的完整 UI 框架。

采用自有轻量 Design System：

```text
desktop/ui/
├── theme.py            # 颜色、字体、间距、圆角、全局 QSS
├── components.py       # Card / StatCard / StatusChip / SectionTitle 等
├── dashboard_window.py
├── onboarding_window.py
├── settings_dialog.py
└── tray.py
```

如实现过程中发现 `components.py` 过大，可再拆分，但不要为了“组件化”引入复杂前端框架。

## 4. Design System

### 4.1 颜色

V1 仅定义一套浅色 token：

- App Background：冷灰白。
- Surface / Card：白色。
- Border：极浅灰。
- Primary：商务蓝。
- Primary Hover：略深商务蓝。
- Text Primary：深灰黑。
- Text Secondary：中灰。
- Success：绿色。
- Warning：琥珀色。
- Error：红色。
- Disabled：浅灰。

颜色只承担层级和状态，不用于装饰性大面积铺色。

### 4.2 字体

优先使用系统字体：

- macOS：系统 SF 字体族。
- Windows：Segoe UI。
- 其他环境：Qt 系统默认 sans-serif。

禁止把外部字体文件打包给用户。

字体层级建议：

- 页面标题：24–28px 等效视觉层级。
- 卡片大数字：26–32px。
- Section 标题：14–16px，中等字重。
- 正文：13–14px。
- 辅助信息：12–13px。

### 4.3 间距与圆角

统一使用 8px 基础节奏：

- 8 / 12 / 16 / 24 / 32。
- 页面外边距优先 24 或 32。
- 卡片内部间距优先 16 或 20。
- 卡片圆角 12–16。
- 输入框 / 按钮圆角 8–10。

### 4.4 控件层级

按钮分三类：

1. Primary：蓝色实心，例如“立即检查邮件”“下一步”。
2. Secondary：白底边框，例如“暂停工作”“测试连接”。
3. Tertiary / Text：轻量文字入口，例如“查看全部”“高级设置”。

禁止所有按钮都使用相同灰色默认 Qt 样式。

### 5.1 Dashboard 信息层级

顶部：

- 产品名。
- 次级说明 `AI Foreign Trade Assistant`。
- 当前状态 chip。
- 设置入口。

今日概览：

- 今日扫描。
- 新询盘。
- 已生成草稿。

服务状态：

- 邮箱。
- AI。
- 企业微信。

学习状态与服务状态分开：

- 历史邮件：已完成。
- 回复风格：已学习。
- 客户记忆：已同步。

不再把“企业微信连接”和“历史学习”混为同一类状态。

### 5.2 最近处理

默认只显示最近 10 条。

从当前大空表格改为紧凑列表 / card row。

每条只显示：

- 发件人。
- 主题。
- 处理时间。
- 草稿状态。
- 企业微信通知状态，如需要。

禁止显示完整客户邮件正文。

### 5.3 操作

主操作：

- `立即检查邮件`，Primary。

次操作：

- `暂停工作` / `继续工作`，Secondary。

设置放右上角，不再作为底部同等级按钮。

Desktop V1 仍然没有任何“发送邮件”按钮。

## 6. 应用状态显示

状态映射保持现有 `AppStatus`：

- `WAITING_INITIALIZATION`：灰色，等待首次配置。
- `RUNNING`：绿色，正在运行。
- `PAUSED`：灰色，已暂停。
- `NEEDS_ATTENTION`：琥珀色，需要处理一个问题，但仍可工作。
- `SERVICE_ERROR`：红色，核心服务异常。

视觉表现优先使用“小圆点 + 文字 / StatusChip”，避免满屏 Emoji。

## 7. 暂停状态

用户点击“暂停工作”后：

```text
● 已暂停

自动检查已暂停
上次检查：14:32
下次检查：已暂停

[继续工作]     [立即检查邮件]
```

行为保持现有 Scheduler 规则：

- 暂停只停止自动轮询。
- `立即检查邮件` 仍允许人工触发一次。
- 暂停不退出软件。
- 暂停不删除任何状态。

## 8. 首次配置向导

首次启动采用 5 步向导：

```text
邮箱 → 身份 → AI → 企业微信 → 历史学习
```

可以增加欢迎页，但欢迎页不计入业务步骤。

顶部使用简洁 Stepper：

```text
●────●────○────○────○
邮箱   身份   AI   企业微信   学习
```

### 8.1 欢迎页

内容：

- 产品名。
- 简短说明。
- “约 3 分钟完成配置”。
- `开始配置` Primary 按钮。

### 8.2 邮箱页

显示：

- 163 邮箱地址。
- 邮箱授权码。
- 测试连接。
- 安全提示：授权码仅保存在系统安全凭据中。

不显示 IMAP Host、Port、SSL。

测试成功后才能进入下一步。

### 8.3 身份页

显示：

- 姓名。
- 职位，可选。
- 公司，可选。
- 签名预览。

### 8.4 AI 页

普通用户只看到：

```text
AI 服务
● 已配置

数字员工已经连接 AI 服务，
无需额外设置。
```

普通用户不显示：

- API Key。
- 模型名。
- Base URL。

如果 AI 尚未由管理员配置完成：

```text
AI 服务尚未完成配置
请联系管理员完成设置。
[进入管理员设置]
```

未配置 AI 时不得继续进入正式运行。

### 8.5 企业微信页

显示：

- Webhook 输入框，默认掩码。
- `测试企业微信`。
- 成功状态。

默认启用企业微信。若启用，则测试通过后才能继续。

### 8.6 历史学习页

历史学习是 **Fresh Install 必做步骤**，不提供“跳过”“稍后学习”。

显示：

```text
让数字员工学习你的历史邮件

历史邮件只用于学习你的回复习惯，
不会回复旧邮件，也不会发送任何邮件。

[开始学习我的历史邮件]
```

普通用户不显示：

- 6 个月。
- 1000 封。
- INBOX / Sent 技术规则。
- 数据库路径。

学习期间：

- 禁用完成按钮。
- Scheduler 不启动。
- Production Gate 保持关闭。

只有以下全部成功后才允许完成：

1. 历史学习没有失败。
2. `initial_learning_completed == "true"`。
3. processed baseline 成功建立。
4. `baseline_completed == True`。
5. `onboarding_completed == True`。

失败时留在本页，显示可理解的错误并允许重试。

## 9. 首次配置完成页

历史学习和 baseline 成功后显示：

## 11. 管理员模式

V1 延续既定的 6 位管理员 PIN 设计。

已确认的使用方式：

- 首次安装时由管理员设置 PIN。
- 普通用户平时不需要知道 PIN。
- PIN 只用于防止普通用户误改高级配置。
- PIN 不作为敏感凭据加密密钥。
- PIN 不明文保存。

进入管理员设置前弹出小型验证对话框。

管理员设置包含：

### AI 服务

- API Key，掩码。
- 模型。
- Base URL。
- 测试 AI 配置 / 构造状态。

### 邮件服务

- IMAP Host。
- Port。
- 邮箱高级状态。
- 扫描间隔。

### 企业微信

- Webhook，掩码。
- 测试通知。
- 启用 / 关闭总开关。

### 历史学习

- 学习月份。
- 最大邮件数。
- 重新学习。

### 系统

- 日志级别。
- 开机启动。
- 备份 / 恢复。
- 导出诊断包。

敏感值继续通过 `CredentialStore` 写入 Keychain / Credential Manager，不写进普通 JSON 设置。

## 12. 错误与异常 UI

普通用户不显示 Python Traceback。

错误采用顶部 Banner / Inline Alert。

### 12.1 邮箱认证失效

```text
邮箱需要重新连接

数字员工暂时无法检查新邮件。
请重新验证邮箱授权码。

[重新连接]
```

核心操作按钮在 `SERVICE_ERROR` 下禁用，设置入口保持可用。

### 12.2 AI 服务异常

```text
AI 服务暂时不可用

邮件仍然安全保留，没有自动发送任何内容。

[检查 AI 设置]
```

### 12.3 企业微信失败

企业微信失败不升级为整个邮件链路失败：

```text
● 邮件处理正常
⚠ 企业微信通知失败
```

必须继续保持现有安全规则：企业微信失败不能破坏已成功保存的草稿。

## 13. 系统托盘 / macOS 菜单栏

菜单保持短而清楚：

```text
● 外贸数字员工正在运行
打开主界面
立即检查邮件
暂停工作 / 继续工作
设置
退出外贸数字员工
```

关闭主窗口不退出程序。

只有点击“退出外贸数字员工”才：

1. 停止 Scheduler。
2. 清理必要资源。
3. 退出 QApplication。

## 14. 安全与隐私 UI 约束

所有页面继续遵守：

- 不显示完整客户邮件正文作为 Dashboard 状态。
- 不显示明文邮箱授权码。
- 不显示明文 AI API Key。
- 不显示明文企业微信 Webhook。
- 不提供发送客户邮件按钮。
- 不允许首次历史学习未完成时开始生产轮询。
- 不允许 UI 绕过 `OnboardingService.is_ready_for_production()`。

## 15. 跨平台视觉原则

同一套布局和组件逻辑运行于 macOS 与 Windows。

允许少量平台自然差异：

- 系统字体。
- 原生窗口边框。
- 系统托盘 / 菜单栏承载方式。

不为了完全像素一致而覆盖操作系统原生行为。

验收重点是：

- 层级一致。
- 控件不溢出。
- 中文显示完整。
- 125% / 150% Windows DPI 下仍可用。
- macOS Retina 下无明显模糊。

## 16. UI 测试策略

继续遵循 RED -> GREEN -> focused regression -> full regression。

新增 / 调整测试至少覆盖：

1. Design System 关键组件可以 offscreen 创建。
2. Dashboard 统计卡片正确渲染。
3. Dashboard 最近处理最多 10 条。
4. Dashboard 没有发送按钮。
5. RUNNING / PAUSED 状态切换按钮文案正确。
6. WAITING_INITIALIZATION / SERVICE_ERROR 禁用生产操作。
7. 首次向导 Stepper 顺序正确。
8. 邮箱测试未通过不能下一步。
9. AI 未配置不能继续。
10. 企业微信启用时测试未通过不能继续。
11. 历史学习页不存在跳过按钮。
12. 历史学习失败不能进入 Dashboard。
13. baseline 未完成不能启动 Scheduler。
14. 配置完成后进入 Dashboard 并自动启动 Scheduler。
15. 普通设置不显示高级技术字段。
16. 管理员 PIN 未通过时高级设置不可见。
17. 页面不显示敏感凭据明文。

真实 UI 预览必须至少在：

- macOS 开发机。
- Windows 最终目标机。

各做一次人工视觉验收。

## 17. 实施顺序

新的 UI 实施顺序覆盖旧 Task 8 的视觉实现细节：

1. 建立 `theme.py` 与基础 Design System。
2. 将现有 Dashboard 改造成 Fluent 浅色布局。
3. 运行 Dashboard offscreen + full regression。
4. 实现同风格首次配置向导。
5. 接入真实 `OnboardingService` 与 baseline Gate。
6. 实现普通设置页。
7. 实现管理员 PIN Gate 与高级设置页。
8. 实现统一错误 Banner / 状态组件。
9. 接入系统托盘视觉与菜单。
10. macOS 真机视觉预览。
11. Windows 真机视觉验收。

旧版 Task 8 示例代码不再直接执行，应以本补充规范和更新后的实施计划为准。

## 18. V1 明确不做

- 深色模式。
- QML 重构。
- 大量复杂动画。
- 自定义无边框窗口系统。
- 邮件正文阅读器。
- 桌面端发送邮件。
- 为了视觉效果加入重型 Web 前端运行时。

## 19. 最终产品体验原则

1. 普通用户打开软件，第一眼只看到当前是否正常工作。
2. 普通用户不需要理解 IMAP、API、模型或历史参数。
3. 主页面只呈现“今天发生了什么”和“是否需要我处理”。
4. 高级配置进入管理员区，不污染普通使用路径。
5. 错误信息先告诉用户“发生了什么、是否安全、下一步做什么”。
6. 视觉设计服务于可信赖和高效，不服务于炫技。
7. 安全边界优先于视觉便利。
8. 历史学习必须完成，软件才进入正式运行。
9. 软件学习用户，而不是要求用户学习软件。
