# 外贸数字员工 Desktop V1 设计

日期：2026-09-16

## 1. 目标

把当前已经验证过的 Python 外贸数字员工，从“需要终端运行的工程项目”封装成普通用户可以直接安装和使用的桌面软件，同时保留现有邮件处理、AI 分析、历史学习、去重、企业微信通知和“只生成草稿、不自动发送”的安全边界。

Desktop V1 的最终用户体验：

1. 安装软件。
2. 首次由管理员完成必要配置。
3. 以后电脑开机后软件自动启动并进入工作状态。
4. 软件后台每 3 分钟检查一次新邮件。
5. 新询盘经过过滤、去重、历史上下文和 AI 分析后，在 163 邮箱中创建英文回复草稿。
6. 企业微信发送内部提醒。
7. 用户到 163 邮箱中人工修改、确认并发送。

任何路径都不得自动向客户发送邮件。

## 2. V1 范围

### 2.1 支持范围

- macOS 与 Windows 共用一套 Python 业务源码。
- 桌面界面使用 PySide6。
- 单机、单用户、单邮箱。
- V1 仅支持 163 邮箱。
- 使用现有 `mail_reader`、`mail_writer`、`agent`、`history_learning`、`wecom` 等核心模块，不重写现有业务逻辑。
- 本地运行、本地历史学习、本地客户记忆。
- 企业微信群机器人 Webhook 通知。
- AI 只生成回复草稿。
- 客户回复草稿统一使用英文。
- 内部继续保留客户语言识别、中文翻译和中文回译。

### 2.2 V1 明确不做

- 不自动向客户发送邮件。
- 不在桌面软件内直接发送邮件。
- 不做完整邮件客户端。
- 不支持 Gmail、Outlook、QQ 邮箱。
- 不支持一台电脑同时监听多个邮箱。
- 不做多用户、多 Profile、团队共享数据库。
- 不做 SaaS、云端账号系统、手机 App。
- 不做自动软件更新。
- 不做企业微信双向控制。
- 不做向量数据库或模型微调。

## 3. 总体架构

采用“一套源码，两套安装包”的结构。

```text
Desktop App
│
├── PySide6 UI
│   ├── 首次配置向导
│   ├── Dashboard
│   ├── 普通设置
│   ├── 管理员设置
│   └── 系统托盘
│
├── Desktop Service Layer
│   ├── 启动 / 暂停
│   ├── 3 分钟轮询
│   ├── 手动立即检查
│   ├── 状态统计
│   ├── 错误恢复
│   └── 后台 Worker
│
├── Platform Adapter
│   ├── macOS
│   │   ├── Keychain
│   │   └── LaunchAgent
│   └── Windows
│       ├── Credential Manager
│       └── 开机启动
│
└── Existing Core
    ├── mail_reader
    ├── mail_writer
    ├── agent
    ├── history_learning
    └── wecom
```

桌面层只负责配置、状态展示、调度和平台适配。现有业务核心继续作为唯一的邮件处理实现，避免出现 GUI 版与命令行版两套业务逻辑。

## 4. 桌面运行模型

### 4.1 启动行为

当邮箱、AI 和企业微信配置有效时，软件启动后自动进入工作状态，不要求用户再次点击“开始工作”。

### 4.2 轮询

默认每 3 分钟检查一次新邮件。

V1 使用稳定的 IMAP 定时轮询，不使用 IMAP IDLE 长连接。高级设置允许管理员未来调整轮询间隔，但普通用户不需要看到该参数。

### 4.3 立即检查

Dashboard 提供“立即检查一次”按钮，用于测试或需要马上检查新邮件的场景。

一次手动检查不能创建第二套处理逻辑，必须复用与定时轮询相同的生产处理入口。

### 4.4 暂停

“暂停工作”只停止自动邮件扫描，不退出桌面应用，不删除配置，不影响查看状态和进入设置。

### 4.5 关闭窗口

关闭主窗口不退出程序。

- macOS：应用继续在菜单栏/后台运行。
- Windows：应用继续在系统托盘运行。

只有用户明确选择“退出外贸数字员工”时，程序才真正停止。

## 5. 首次配置向导

首次启动时进入向导。完成配置前不得静默开始生产邮件处理。

### 5.1 邮箱配置

普通用户填写：

- 163 邮箱地址。
- 邮箱授权码。

提供“测试连接”按钮。

普通用户不显示 IMAP Host、Port、SSL 等技术参数。163 默认参数由程序自动提供；高级参数仅在管理员设置中可见。

邮箱授权码进入操作系统安全凭据存储，不写入正式版明文 `.env`。

### 5.2 用户身份

填写：

- 姓名。
- 职位，可留空。
- 公司，可留空。

界面提供邮件签名预览。

身份信息属于当前安装实例的用户配置，不写死在源码中，并允许以后修改。

### 5.3 AI 服务

由管理员预配置，普通用户默认只看到：

`AI 服务：✅ 已配置`

API Key、模型名、Base URL 等只放在管理员设置。

API Key 不得写死进安装包；由管理员首次输入后保存到系统安全凭据存储。

### 5.4 企业微信

配置现有企业微信群机器人 Webhook，并提供“测试企业微信”按钮。

测试成功时发送内部测试消息：

```text
✅ 外贸数字员工已连接

邮箱连接正常
AI 服务正常
企业微信通知正常

数字员工已经可以开始工作。
```

Webhook 属于敏感凭据，保存到系统安全凭据存储。

### 5.5 开机自动运行

首次配置时显示：

`☑ 开机后自动启动外贸数字员工`

默认勾选，但允许用户取消。之后普通设置中仍可修改。

## 6. 历史学习接入

首次基础连接完成后，主动提示用户学习历史邮件。

界面只显示简单入口：

`开始学习我的历史邮件`

普通用户不需要看到默认参数。后台沿用现有历史学习规则：

- 最近 6 个月。
- 最多 1000 封。
- 只读取 INBOX + Sent。
- 历史邮件只用于学习和建立上下文。
- 历史邮件不得生成新回复草稿。
- 初次学习完成后建立 processed baseline。
- baseline 之后的新邮件才进入自动处理流程。

历史学习必须保持用户主动触发，不能在绑定邮箱后偷偷扫描历史邮箱。

## 7. Dashboard

Dashboard 只承担“状态驾驶舱”职责，不做完整邮箱客户端。

建议展示：

- 当前状态。
- 上次检查时间。
- 下次检查时间。
- 今日扫描邮件数。
- 今日新询盘数。
- 今日已生成草稿数。
- 最近 10 条处理记录。
- 历史学习状态。
- 回复风格状态。
- 企业微信连接状态。
- “暂停工作”。
- “立即检查一次”。
- 设置入口。

统一状态：

- 🟢 正在运行
- 🟡 已暂停
- 🟠 需要处理
- 🔴 服务异常

Dashboard 不展示完整客户邮件正文。

## 8. 最近处理记录

最近处理列表默认只显示最近 10 条。

每条可展示：

- 客户/发件人。
- 邮件主题。
- 处理时间。
- 草稿状态。
- 企业微信通知状态。

进入单条详情后可显示：

- 客户。
- 主题。
- 处理时间。
- AI 分析是否完成。
- 163 草稿是否已保存。
- 企业微信是否已通知。

提供“打开邮箱查看草稿”入口。

Desktop V1 不提供“发送”按钮。

## 9. 回复语言与安全策略

保持现有生产 Skill 的规则：

- 自动识别客户原始语言。
- 内部显示中文翻译。
- `Reply Draft` 始终使用英文。
- 内部显示完整中文回译。
- 保留现有 Output Gate 和商业事实校验规则。
- 历史商业信息不得被当作当前有效事实。
- 任何客户邮件均只创建草稿。
- 最终发送必须由人工在 163 邮箱中完成。

桌面化不得降低或绕过这些安全规则。

## 10. 系统托盘 / 菜单栏

托盘菜单至少包含：

- 打开外贸数字员工。
- 暂停工作 / 恢复工作。
- 立即检查。
- 设置。
- 退出外贸数字员工。

窗口关闭与应用退出必须是两个不同动作。

## 11. 普通设置

普通用户可以修改：

- 姓名。
- 职位。
- 公司。
- 邮件签名。
- 企业微信连接状态。
- 开机自动运行。
- 桌面通知开关。
- 重新测试邮箱。
- 重新测试企业微信。

普通设置不展示 API Key、模型、Base URL、IMAP Host、日志级别等技术参数。

## 12. 管理员模式

高级设置通过 6 位管理员 PIN 保护。

首次安装时由管理员设置 PIN。

管理员设置包含：

- AI API Key。
- AI 模型。
- Base URL。
- 邮箱高级参数。
- 轮询间隔。
- 历史学习范围。
- 最大历史邮件数。
- 日志级别。
- 重新学习历史邮件。
- 备份数据。
- 恢复数据。
- 导出诊断包。

PIN 只用于防止普通用户误改高级设置，不作为敏感凭据加密密钥。

PIN 不保存明文，使用随机 salt + 安全密码哈希保存。

提供本机管理员重置入口，避免忘记 PIN 后只能卸载重装。敏感 API Key、邮箱授权码和 Webhook 的保护仍由系统安全凭据存储承担。

## 13. 凭据安全

正式桌面版的敏感凭据包括：

- 邮箱授权码。
- AI API Key。
- 企业微信 Webhook。

保存方式：

- macOS：Keychain。
- Windows：Credential Manager。

普通配置可以保存为本地配置文件，但敏感凭据不得明文写入该配置文件。

开发环境可以继续使用 `.env`，但正式桌面版运行不能依赖 `.env` 才能启动。

界面中敏感字段默认只显示掩码，例如 `••••••••`。

日志、诊断包和错误消息不得输出敏感凭据。

## 14. 开机启动

V1 支持跨平台开机启动：

- macOS：通过平台适配层管理 LaunchAgent 或等价稳定机制。
- Windows：通过平台适配层管理用户级启动机制。

平台差异必须封装在独立 adapter 中，业务层和 UI 不直接依赖平台命令。

开机自动运行默认开启，但用户可以在普通设置中关闭。

## 15. 错误处理与自动恢复

普通用户不直接看到 Python Traceback。

UI 只展示可理解的错误，例如：

```text
邮箱连接失败

可能是邮箱授权码已经失效，
或者当前网络暂时不可用。

[重新连接] [稍后再试]
```

管理员日志记录技术细节。

容错原则：

1. 单次邮箱连接超时：保留运行状态，下个轮询周期自动重试。
2. 企业微信通知失败：不得影响已经成功保存的邮件草稿。
3. 历史学习增量同步失败：不得阻塞正常新邮件处理。
4. AI 调用失败：该邮件保持可重试状态，不创建空白或错误草稿，也不错误标记为已处理。
5. 单次失败不立即把整个应用判定为“服务异常”。
6. 连续失败达到明确阈值后，状态升级为“需要处理”或“服务异常”。
7. 恢复成功后状态自动回到正常运行。

具体连续失败阈值在实施计划中定义并用测试固定。

## 16. 用户数据目录

程序文件与用户数据彻底分离。

程序安装目录只保存应用本身。

用户数据目录保存：

- 普通设置。
- 管理员 PIN 哈希数据。
- `history_learning.db`。
- processed Message-ID 状态。
- Dashboard 运行状态。
- 日志。
- 备份。

用户数据目录使用操作系统推荐的用户级应用数据路径，由平台适配层统一解析。

升级或重新安装程序不得清空历史学习、客户记忆、配置和 processed 状态。

## 17. 日志与诊断

默认日志保留 30 天并自动清理。

日志不得记录：

- API Key。
- 邮箱授权码。
- 企业微信 Webhook。
- 完整客户邮件正文。

管理员模式提供“导出诊断包”。

诊断包只包含排障需要的非敏感信息，例如：

- 软件版本。
- 操作系统信息。
- 配置状态摘要。
- 脱敏后的错误日志。
- 关键模块健康状态。

## 18. 备份与恢复

管理员模式提供手动：

- 备份数据。
- 恢复数据。

普通备份包含：

- 历史学习数据库。
- 客户记忆。
- 回复风格。
- 非敏感程序设置。
- processed Message-ID 状态。

普通备份默认不包含：

- AI API Key。
- 邮箱授权码。
- 企业微信 Webhook。

换电脑恢复后，需要重新输入敏感凭据。

## 19. 卸载策略

卸载时默认保留用户数据。

界面/安装器应明确提供：

`☑ 保留我的配置和学习数据`

只有用户明确选择“删除所有本地数据”时，才删除历史数据库、客户记忆、设置和日志。

## 20. 打包与发布

### 20.1 macOS

目标产物：

- `.app`
- `.dmg`

优先使用 PyInstaller 打包 Python + PySide6 桌面应用，再生成可分发 DMG。

### 20.2 Windows

目标产物：

- 可运行的 PyInstaller 程序。
- 面向普通用户的 `Setup.exe` 安装程序。

Windows 安装程序可使用 Inno Setup 或同类成熟工具。

最终 Windows 用户不需要安装：

- Python。
- pip。
- Git。
- VS Code。
- Terminal / PowerShell 开发环境。

### 20.3 自动更新

V1 不实现自动更新。

软件保留版本号，例如 `v1.0.0`。后续版本通过重新安装升级，但升级过程必须保留独立用户数据目录。

## 21. 测试策略

继续沿用现有测试先行流程：

```text
RED
 -> GREEN
 -> focused regression
 -> full regression
 -> real mailbox
 -> desktop test
 -> package test
 -> git commit
 -> git push
```

现有核心测试必须继续全部通过。桌面化不得通过删除、跳过或弱化现有测试来换取通过率。

Desktop V1 至少需要覆盖：

1. 首次配置状态机。
2. 邮箱测试连接成功/失败。
3. AI 配置状态检查。
4. 企业微信测试通知成功/失败。
5. 历史学习按钮与完成状态。
6. 初次历史学习后 baseline 正确建立。
7. 3 分钟轮询调度。
8. “立即检查一次”复用同一生产处理入口。
9. 暂停后不再自动扫描。
10. 恢复后继续扫描。
11. 关闭窗口后后台继续运行。
12. 明确退出后后台停止。
13. 系统托盘菜单行为。
14. 开机自启动开启/关闭。
15. 管理员 PIN 正确、错误和重置流程。
16. 敏感凭据不进入普通配置文件。
17. 日志不泄露敏感凭据和完整客户正文。
18. AI 失败时邮件保持可重试且不误标 processed。
19. 企业微信失败不影响已创建草稿。
20. 历史增量学习失败不影响正常新邮件处理。
21. 程序升级/重装不清理用户数据。
22. 备份/恢复不默认包含敏感凭据。
23. 同一新邮件不会重复创建草稿或重复通知。
24. 任何路径都不得自动发送客户邮件。
25. Mac 与 Windows 的核心行为保持一致。

## 22. Mac 真实验收

先在开发者 Mac 上完成完整验收：

1. 安装桌面应用。
2. 完成首次配置。
3. 执行历史学习。
4. 确认软件自动进入运行状态。
5. 从外部邮箱发送一封真实测试询盘。
6. 点击“立即检查一次”或等待轮询。
7. 验证 AI 正确处理。
8. 验证 163 草稿箱出现英文草稿。
9. 验证企业微信通知成功。
10. 验证 Dashboard 更新。
11. 再检查一次，确认不重复生成草稿和通知。
12. 关闭主窗口，确认后台继续运行。
13. 重启电脑，确认开机自动启动并恢复工作。

## 23. Windows 最终验收

最终必须在真实 Windows 环境完成安装与运行验证，不能仅凭 macOS 测试推断跨平台可用。

成功标准：

> 普通 Windows 用户在没有 Python、Git、VS Code 的电脑上，完成一次安装和初始化后，可以依靠开机自动运行完成“新邮件检测 -> AI 草稿 -> 企业微信提醒”，全程不需要终端操作，并且任何情况下都不会自动向客户发送邮件。

Windows 验收还必须验证：

- `Setup.exe` 可正常安装和卸载。
- Credential Manager 正常保存和读取敏感凭据。
- 开机自动启动正常。
- 系统托盘正常。
- 163 邮箱真实连接正常。
- 历史学习正常。
- 新询盘只生成一个草稿。
- 企业微信通知一次且顺序正确。
- 重装新版本后用户数据仍保留。

3. Phase 3：邮箱 / AI / 企业微信首次向导。
4. Phase 4：History Learning UI。

6. Phase 6：系统托盘 + 开机启动。
7. Phase 7：管理员模式 + PIN。

9. Phase 9：macOS 打包和真实邮箱验收。
10. Phase 10：Windows 打包和实机验收。

每个阶段必须在进入下一阶段前完成相应测试和回归，避免一次性把桌面 UI、系统集成和打包问题混在一起排查。

## 25. 设计原则总结

Desktop V1 必须始终遵守以下原则：

1. 一套业务核心，不复制第二套邮件处理逻辑。
2. Mac 与 Windows 共用绝大多数源码，平台差异集中在 adapter。
3. 普通用户只看到必要信息，高级技术参数放入管理员模式。
4. 敏感凭据交给操作系统安全存储，不写死、不明文落盘。
5. 历史邮件只学习，不回复。
6. 新邮件按现有 eligibility、去重、历史上下文、AI、安全校验、草稿、企业微信流程处理。
7. AI 失败时宁可待重试，也不能生成错误草稿或误标 processed。
8. 任何时候都不自动向客户发送邮件。
9. 关闭窗口不等于退出程序。
10. 程序升级不等于清空用户数据。
11. Mac 先完整验证，Windows 必须再做真实实机验收。
12. 功能逐阶段落地，每阶段保持自动化测试和真实链路验证。
